# 构建与自测

## 一、环境要求

| 项目 | 要求 | 本机实测值 |
|---|---|---|
| 编译器 | **MSVC**（不能用 MinGW） | 19.44.35229 |
| 平台 | x64 | x64 |
| Windows SDK | 含 `xamlOM.h` | 10.0.22621 / 10.0.26100 |
| CMake | ≥ 3.20 | 随 VS Build Tools 提供 |
| Ninja | 任意版本 | 随 VS Build Tools 提供 |

### 为什么必须用 MSVC

1. `GlassTAP.dll` 用了 **C++/WinRT**（`winrt::implements`、`winrt::com_ptr`），
   它依赖 MSVC ABI 与 `__declspec(uuid)`，GCC 编不了。
2. `xamlOM.h` 用了 `MIDL_INTERFACE` 宏，MinGW 的头文件里没有。

本机 MinGW 路径（**不可用于本项目**，仅记录）：
- `D:\Tools\Qt\Tools\mingw1310_64\bin\g++.exe`（13.1.0，posix 线程）
- PATH 上的 `g++` 是 8.1.0 win32 线程版，连 `std::thread` 都没有

## 二、构建

### 一键构建

```powershell
cd C:\hot_rain\cpp\hotrainy

$bt = "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools"
$vcvars = "$bt\VC\Auxiliary\Build\vcvars64.bat"
$ninja  = "$bt\Common7\IDE\CommonExtensions\Microsoft\CMake\Ninja"

# 用 vcvars 初始化 MSVC 环境后构建
cmd /c "call `"$vcvars`" >nul 2>&1 && cd build && cmake -G Ninja -DCMAKE_BUILD_TYPE=Release .. && ninja"
```

首次配置需要先生成 build 目录：

```powershell
cd C:\hot_rain\cpp\hotrainy
mkdir build -Force
cd build
cmd /c "call `"$vcvars`" >nul 2>&1 && cmake -G Ninja -DCMAKE_BUILD_TYPE=Release .."
cmd /c "call `"$vcvars`" >nul 2>&1 && ninja"
```

### 产物

```
build/hotrainy.exe     主程序
build/GlassBoot.dll    引导层（纯 C）—— 必须和 hotrainy.exe 同目录
build/GlassTAP.dll     功能层（C++/WinRT）—— 同上
```

**三个文件必须放在同一个目录**：引导层按自身所在目录查找 `GlassTAP.dll`。

### 部署

```powershell
Copy-Item build\hotrainy.exe, build\GlassBoot.dll, build\GlassTAP.dll `
          C:\hot_rain\dist_v3\hotrainy\ -Force
```

## 三、自测清单

### 3.1 编译产物完整性

```powershell
# 三个文件都要存在
Test-Path build\hotrainy.exe, build\GlassBoot.dll, build\GlassTAP.dll
```

### 3.2 导出表检查

引导层必须导出三个符号，缺任何一个功能都不工作：

```powershell
$dumpbin = "<VS>\VC\Tools\MSVC\<ver>\bin\Hostx64\x64\dumpbin.exe"
& $dumpbin /EXPORTS build\GlassBoot.dll | Select-String "GlassBoot_|DllGetClassObject"
```

预期：

```
DllGetClassObject      系统建立诊断通道后索取 TAPSite
GlassBoot_HookProc     钩子过程 —— 缺它 DLL 无法在 explorer 常驻
GlassBoot_Shutdown     清理入口
```

功能层：

```powershell
& $dumpbin /EXPORTS build\GlassTAP.dll | Select-String "DllGetClassObject"
```

### 3.3 依赖检查

引导层必须**只有** `USER32.dll` 和 `KERNEL32.dll`。
出现 `MSVCP140.dll` / `VCRUNTIME140.dll` / 任何 C++ 运行时，
说明它不再"纯净"，`InitializeXamlDiagnosticsEx` 会失败：

```powershell
& $dumpbin /DEPENDENTS build\GlassBoot.dll
```

### 3.5 还原测试

```powershell
# 关闭透明
# 把 taskbarTransparent 设为 false 并重启主程序
```

预期：
- `Opacity` 被写回 1
- 任务栏恢复系统默认外观
- `cpp.log` 里出现 `taskbar: 关闭透明（还原）-> 成功`

**关键**：即使主程序异常退出（任务管理器强杀），

## 四、诊断工具

保留在 `tools/` 下，构建后可用于排查：

| 工具 | 用途 |
|---|---|
| `inject_diag.cpp` | 逐步诊断注入链路的每一环 |
| `tap_apply.cpp` | 独立测试注入 + 应用透明（不启动主程序） |
| `tb_lifecycle.cpp` | 任务栏服务生命周期自测 |
| `tb_state.cpp` | 读取当前任务栏状态 |
| `shot.cpp` / `cap.cpp` | 截屏辅助 |
| `icon_probe.cpp` | 测量图标区锐度 |
| `settings_shot.cpp` | 截设置界面 |

### 排查注入问题的顺序

1. **先看 `%APPDATA%\hotrainy\cpp.log`**
   有没有 `钩子已装载`？没有 → `SetWindowsHookEx` 就失败了。

2. **再看 `%LOCALAPPDATA%\hotrainy\boot.log`**
   有没有内容？没有 → DLL 没被映射进 explorer。
   有内容但停在 `0x66666666` → 钩子过程不是 DLL 导出的，DLL 被过早卸载。

3. **再看 `%LOCALAPPDATA%\hotrainy\tap.log`**
   停在 `GlassTAP.dll 已载入` 之后 → 视觉树挂载有问题。
   看 `QI callback` 那行的返回值，`0x80004002` 说明接口没列全。

4. **`crash.log`**（如果存在）
   进程内崩溃捕获记录，含调用栈与模块偏移。

## 五、常见错误码对照

| 错误码 | 含义 | 常见原因 |
|---|---|---|
| `0x80070490` | `ERROR_NOT_FOUND` | 进程 COM 状态不干净；调用了 `CoInitializeEx`/`RoInitialize`；DLL 链接了 C++/WinRT |
| `0x80004005` | `E_FAIL` | 在回调栈内改属性；尝试写 `Shape.Fill`（该属性不可写） |
| `0x80004002` | `E_NOINTERFACE` | `implements<>` 漏列了基接口 |
| `0x80070057` | `E_INVALIDARG` | 属性名没写全（要 `类型.属性名`） |
| `0xc0000409` | `__fastfail` | 在 `DllMain` 里调用 `InitializeXamlDiagnosticsEx` |

## 六、系统改动清单

本方案**不修改任何系统设置**：

- ❌ 不写注册表
- ❌ 不改系统主题
- ❌ 不改 DWM 参数
- ❌ 不安服务、不装驱动
- ✅ 只在 explorer 进程内存里改一个 XAML 元素的 `Opacity`

唯一的外部痕迹是 `%APPDATA%\hotrainy\` 和 `%LOCALAPPDATA%\hotrainy\`
下的配置与日志文件。

**卸载 = 删除程序目录**。explorer 重启后一切归零。
