## 一、当前要做的视觉效果（用户口径）

参照 **GlassDesk（`everlosttime/glassdesk-open-source`，非商用许可，只可模仿思路、禁止抄代码）** 的效果图：

| 部位 | 目标 |
|---|---|
| **面板主体** | **纯透明**（不铺任何底色、不雾化；背后的壁纸/画面直接透出来） |
| **边框** | 一圈**极细、看得清**的边 + 内侧一道更亮的高光（玻璃的"厚度感"）；四角**都是圆角** |
| **外阴影** | **柔和**的投影，让面板"浮"在桌面上（**不是**硬黑描边圈） |
| **圆角** | 要**明显**（当前 `px(18)`，用户说"整体再大一点点"） |
| **快捷方式悬停底色** | 鼠标移到某一项时，那一行的底色 = **半透明磨砂**感（现在是不透明的浅灰，且**会伸出面板外**） |
| **标签条上的每个标签** | 也要有**这种圆滑边框**的感觉 |
| **标签条右侧的小图标** | **每一个**都要有**圆滑的框** |

## 六、踩过的坑（都真金白银验证过）

1. **陈旧 obj**：任何**头文件/函数签名**变化后，必须 `ninja -t clean` 再编，否则出现莫名其妙的 `LNK2019`（"无法解析的外部符号"）。
2. **成功判据**：只能看构建日志里 `error [A-Z]+[0-9]+` / `FAILED` 的行数；我一度用"产物时间戳"判断，**误提交了一个编译不过的提交**（已 `git reset` 修掉）。
3. **回滚后要重跑 cmake**：否则 `build.ninja` 仍引用已删除的源文件 → `ninja: error: ... missing and no known rule`。
4. **访问器/包装不要与内部函数同名**：会 `C2668 重载歧义`（例如 `applySetting`→`applySettingKey`、`toggleIslandPanel`→`toggleIslandPanelWire`）。
5. **自定义返回类型**（如 `ContextMenuHooks makeHooks()`）自动生成包装会丢返回类型 → 手工补。
6. **Python 脚本里中文字符串别混英文引号**（会让脚本语法错误、静默不执行，看起来像"改了但没生效"）。
7. **不要用"整体平移画布"来腾阴影空间** —— 它会把 `cutRoundCorners` 切好的三个圆角裁掉、让边框错位、让后画的高亮溢出（本次三条缺陷同源）。
8. 面板是**分层窗口（UpdateLayeredWindow）**：圆角外的像素必须靠 `cutRoundCorners` 清成透明，**系统不会帮你裁**。
