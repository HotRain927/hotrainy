## 一、当前要做的视觉效果（用户口径）

参照 **GlassDesk（`everlosttime/glassdesk-open-source`，非商用许可，只可模仿思路、禁止抄代码）** 的效果图：

| 部位 | 目标 |
|---|---|
| **面板主体** | **纯透明**（不铺任何底色、不雾化；背后的壁纸/画面直接透出来） |
| **边框** | 一圈**极细、看得清**的边 + 内侧一道更亮的高光（玻璃的"厚度感"）；四角**都是圆角** |
| **外阴影** | **柔和**的投影，让面板"浮"在桌面上（**不是**硬黑描边圈） |
| **圆角** | 要**明显**（当前 `px(18)`，用户说"整体再大一点点"） |
| **快捷方式悬停底色** | 鼠标移到某一项时，那一行的底色 = **半透明磨砂**感（现在是不透明的浅灰，且**会伸出面板外**） |
| **标签条上的每个标签** | 也要有**这种圆滑边框**的感觉 |
| **标签条右侧的小图标** | **每一个**都要有**圆滑的框** |

### 本次会话（2026-10-26 凌晨）新增

9. **修掉"边框四角是断口"的真因**（提交 `509148c`）：
   `glass.cpp` 的 `cornerCover()` 把圆角圆心算成 `(r, r)`，只有矩形"够厚"时才成立；
   而边框是 `strokeRoundRect()` 用**四条 1px 细条**拼的（上面那条 h=1），
   圆心落在矩形外 → 四个角的 cover 恒为 0 → **圆角弧整段没画出来**，
   看起来就是四条中间断开、四角有缺口的直线。
   （实测证据：顶边从 `x=左+radius` 才开始、左边从 `y=上+radius` 才开始，中间无像素。）
   改法：`cornerCover` 换成标准圆角矩形 SDF；`strokeRoundRect` 改成按"到路径的距离"真描边。
10. **合成改成真 source-over**（同 `509148c`）：新增 `blendSrcOverA()`，
    `fillRect / fillRoundRect / drawLine / strokeCircle` 改用它。
    旧代码 `blendColor(dst|0xFF000000, c, a) | 0xFF000000` 会把结果 alpha 强写 255 ——
    在**纯透明**面板上，`0x20FFFFFF` 的悬停高亮被算成 `0xFF202020` 的**不透明灰块**
    （用户说的"不透明的浅灰"就是这么来的）。现在透明底 → 半透明，语义正确。
    顺带：`buildFlatPanel` 边框改成 **一暗一亮两道**（1px 暗轮廓 + 内侧 1px 亮高光），
    浅色壁纸和深色背景上都看得清；`panel.cpp` 不再对透明主体 `cutRoundCorners`。
11. **外阴影做完了**（提交 `51bccf7`，用的就是第八节第 2 条要求的"窗口向外扩留白"）：
    - `Surface::applyOuterShadow(contentRect, radius, dark, offsetY)`：**只画内容矩形之外**
      那一圈，按到内容圆角矩形的有符号距离做二次衰减，并强制在画布边界归零
      （所以顶部留白很窄也不会出现硬切线）。刻意不用盒式模糊铺满 —— 那会把
      "纯透明主体"一起压暗。
    - `Surface::blendOver(src,dx,dy)`：内容以 source-over 叠到带留白的画布上。
    - `panel.cpp`：窗口按 左右 `px(14)` / 上 `px(6)` / 下 `px(14)` 外扩
      （顶部特意窄，影子不压标签栏），**内容坐标一像素不动**；提交时 `dst = 内容位置 - 留白`；
      `handle()` 里所有鼠标命中原点都减掉留白。
    - 实测窗口 `(790,36)-(1625,466)` = 内容 `(811,45,793x400)` + 留白 `21/9/21/21`。
12. **用户看过后说"现在这个样子就好"** —— 于是第八节第 3 步（面板再大一点点）当时没做；
    但随后又提了下面 13～16 四条**功能/边框**要求，都已做完（提交 `07e927f`）。
13. **快捷方式图标不显示 → 修好**：`drawBitmapFaded` 只写 RGB、保留底原来的 alpha
    （`dst = (dst & 0xFF000000) | rgb`）。这在"不透明玻璃底"上没问题，但面板主体是
    纯透明（alpha=0）→ 图标被画上去却仍然全透明，**一个都看不见**。
    改成标准 source-over、alpha 一起写回（顺带修 opacity<1 时预乘色没跟着乘的偏差）。
14. **面板里的快捷方式点不到 → 修好**：分层窗口的命中测试**只看 alpha**，面板主体
    alpha=0 → 鼠标直接穿透到背后的窗口。
    实测证据：修之前 `WindowFromPoint(1400,230)` / `(840,230)` 返回的是背后的 Chrome 窗口，
    只有边框和阴影那几圈返回 `HotrainyPanel`；修完两个点都返回 `HotrainyPanel`。
    修法：`Surface::ensureHitTestableArea()` 把内容区（圆角内）的 alpha 抬到 1
    （1/255 ≈ 0.4%，肉眼不可见）。顺带把"悬停高亮不亮"也修了 —— 之前连 `WM_MOUSEMOVE`
    都收不到，因为鼠标压根没进这个窗口。
15. **文字没跟设置走 → 修好**：`textMain_ / textDim_` 是成员默认值（写死，正好等于深色那套），
    `setDark()` 从不更新它们 → 设置里选「深色文字」时面板/标签栏还在画白字。
    改成从 `theme.cpp` 的全局玻璃调色板取色（和岛台同一个来源）。
16. **标签栏：每个标签、每个右侧图标各一圈"类矩形圆角"框**（同时把悬停的快捷方式条也做成
    "半透明底 + 亮起来的框"）：
    - 新增 `Surface::strokeGlassEdge()`（外圈 1px 暗轮廓 + 内侧 1px 亮高光）；
      **面板边框也改成调它** —— 所以标签/图标/悬停行跟面板是"一个感觉"。
    - 每个标签的框**一直显示**（不是悬停才出现）、横向**铺满整个标签格**、纵向只留 1px
      （用户："这个框的大小要撑满本来的标签"）、圆角 `px(4)`（小圆角，像矩形不像胶囊）；
      悬停/激活把 strength 调到 1.25~1.5 让边变亮。
    - 右侧 4 个小图标同款，各自撑满自己那一格。

## 六、踩过的坑（都真金白银验证过）

1. **陈旧 obj**：任何**头文件/函数签名**变化后，必须 `ninja -t clean` 再编，否则出现莫名其妙的 `LNK2019`（"无法解析的外部符号"）。
2. **成功判据**：只能看构建日志里 `error [A-Z]+[0-9]+` / `FAILED` 的行数；我一度用"产物时间戳"判断，**误提交了一个编译不过的提交**（已 `git reset` 修掉）。
3. **回滚后要重跑 cmake**：否则 `build.ninja` 仍引用已删除的源文件 → `ninja: error: ... missing and no known rule`。
4. **访问器/包装不要与内部函数同名**：会 `C2668 重载歧义`（例如 `applySetting`→`applySettingKey`、`toggleIslandPanel`→`toggleIslandPanelWire`）。
5. **自定义返回类型**（如 `ContextMenuHooks makeHooks()`）自动生成包装会丢返回类型 → 手工补。
6. **Python 脚本里中文字符串别混英文引号**（会让脚本语法错误、静默不执行，看起来像"改了但没生效"）。
7. **不要用"整体平移画布"来腾阴影空间** —— 它会把 `cutRoundCorners` 切好的三个圆角裁掉、让边框错位、让后画的高亮溢出（本次三条缺陷同源）。
8. 面板是**分层窗口（UpdateLayeredWindow）**：**不透明**底的面板，圆角外的像素必须靠 `cutRoundCorners` 清成透明，系统不会帮你裁（纯透明主体见第 11 条）。
9. **分层窗口的命中测试只看 alpha**：`alpha=0` 的像素不接收鼠标，系统直接穿透过去。
   面板主体"纯透明" → 整块面板对鼠标是**空的**：里面的快捷方式点不到，连 `WM_MOUSEMOVE`
   都收不到（所以悬停高亮也不会亮，看起来像"悬停功能坏了"）。
   判据用 `WindowFromPoint()` 实测，别猜。修法：`ensureHitTestableArea()` 把内容区
   alpha 抬到 1（1/255，看不出来）。
10. **在透明底上画任何东西，都必须把 alpha 一起写回**。项目里有两个**同源** bug：
    `blendColor(...) | 0xFF000000`（fill/stroke 系列）和 `drawBitmapFaded` 里的
    `dst = (dst & 0xFF000000) | rgb`（图标）。两者在"不透明玻璃底"上都是**对的**，
    所以一直没暴露；底一改成纯透明，一个把半透明高亮画成不透明灰块，
    另一个把图标画成完全透明（看不见）。改合成公式时先问一句"底是不是透明的"。
11. `cutRoundCorners` 是给"不透明底"准备的（把角上的底色切透明）。主体改成纯透明之后
    **不需要**它了 —— 圆角由 `strokeRoundRect` 的 SDF 描边自己画出来；
    再切一刀只会把边框最外那 1px 的 alpha 削掉一半，等于把刚画好的边削淡。
