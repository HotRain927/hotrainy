# 代码结构

> 这份文档说明：**想改某个功能，应该去哪个目录/文件**。
> 目录重构后（见文末"迁移状态"），每个模块各自成块，模块内部的改动不牵扯其它模块。

## 一、模块目录对照

| 目录 | 负责什么 | 主要文件 |
|---|---|---|
| `src/app/` | 程序入口、启动流程、托盘、**各模块之间的接线**（把 A 的回调接到 B） | `main.cpp` |
| `src/tagbar/` | **顶部标签栏 + 它的悬停面板**（标签条绘制、展开/收起、面板内快捷方式网格） | `bar.cpp`（标签条）、`panel.cpp`（悬停面板） |
| `src/island/` | **岛台面板 + 任务栏那颗 H 按钮 + 任务栏服务**（注入状态机、任务栏透明下发、explorer 重启后重挂钩） | `island.cpp`（岛台面板）、`islandbtn.cpp`（H 按钮）、`taskbar.cpp`（任务栏服务） |
| `src/settings/` | **设置窗**与通用对话框（输入框、文件选择、提示、警告） | `settings.cpp`、`dialog.cpp` |
| `src/search/` | **搜索窗**与文件索引 | `search.cpp` |
| `src/text/` | **文字与主题**：深浅色两套配色、字号、字体、图标字体 | `theme.cpp` |
| `src/audio/` | **音频波动条**（频谱、峰值保持、方向、拖动、持久化） | `audio.cpp` |
| `src/glass/` | **液态玻璃与面板表面**：抓屏、模糊、圆角、**面板底色/边框/整体 alpha**、Surface 绘制原语 | `glass.cpp` |
| `src/shared/` | 公共件：配置读写、通用工具、热键、图标、右键菜单、shell 辅助 | `config.cpp`、`common.cpp`、`hotkey.cpp`、`icons.cpp`、`menu.cpp`、`shell.cpp` |
| `src/tb/xaml/` | **注入侧**（跑在 explorer 里的 DLL）：视觉树访问、通信通道、崩溃守护、引导 DLL | `tapsite.cpp`、`visualtree.cpp`、`injector.cpp`、`channel.cpp`、`glassboot.c`、`crashguard.c` |
| `include/hr/` | 与 `src/` 一一对应的头文件（**目前仍是平铺**，见文末） | `*.h` |
| `third_party/tbg/` | 唯一外部依赖：手写迷你 JSON（vendored） | `json.h` / `json.cpp` |

## 三、几处"只应该有一份"的公共逻辑

重构时特意收敛到这里，**以后不要在各面板里各写一份**：

| 逻辑 | 唯一位置 | 说明 |
|---|---|---|
| 面板底色/边框/圆角 | `glass.cpp` → `Surface::buildFlatPanel(opacity, radius, dark)` | 不铺色底（纯透明）+ 三层错位的极细立体边框 |
| 面板整体透明度 | 各面板提交分层窗口处（`UpdateLayeredWindow` 前一行）缩放 `SourceConstantAlpha`，值来自 `cfg.panelOpacity` | 4 个面板 + 标签条共 5 个提交点 |
| 文字颜色（深/浅两套） | `theme.cpp` 提供配色；`app/main.cpp` 决定用哪套：`g_cfg.taskbarTextColor == L"light"` → 深色主题 | 已删除"自动"档；默认 `dark`（深色文字） |
| 配置读写 | `shared/config.cpp` | 只有一个 JSON 文件：`%APPDATA%\hotrainy\config.json` |

## 四、构建方式

源文件**按模块目录自动收集**，新增文件不需要改 CMake：

```cmake
file(GLOB HR_SOURCES "${CMAKE_SOURCE_DIR}/src/*.cpp")
foreach(mod app tagbar island settings search text audio glass shared)
    file(GLOB _HR_MOD "${CMAKE_SOURCE_DIR}/src/${mod}/*.cpp")
    list(APPEND HR_SOURCES ${_HR_MOD})
endforeach()
```

> ⚠️ 没有用 `GLOB_RECURSE`：否则会把 `src/tb/**`（注入侧，单独一套 target）重复收进主程序。

```bat
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -B build
ninja -C build -j4
```

**改了头文件一定要完整重建**（`ninja -C build -t clean` 后再 build）：本项目曾因陈旧 obj 布局出现两次真实崩溃。

## 六、加/改模块的标准动作

1. **加新模块**：`src/<模块>/xxx.cpp` + `include/hr/xxx.h` → 直接构建（CMake 自动收集）→ 需要跨模块协作时，回调定义放在模块自己的头文件里，由 `app/main.cpp` 接线。
2. **改现有模块**：只动该模块目录内的文件；若需要访问别的模块，通过 `app/main.cpp` 里已有的 hook 机制，不要在模块之间直接互相调用。
3. **加设置项**：`settings.cpp` 加一行（`toggle/segmented/slider/button`）+ `config.h`/`config.cpp` 加字段与读写 + `app/main.cpp` 的 `applySetting()` 加生效分支。
