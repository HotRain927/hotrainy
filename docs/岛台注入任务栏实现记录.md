# 岛台控件注入系统任务栏 —— 技术实现记录

## 一、这个文档记什么

岛台的按钮**不是独立窗口**，而是真正插进 explorer 的任务栏 XAML 树里的一个控件。
它和开始按钮、任务图标同级，占据任务栏最左端（原开始按钮的位置）。

这条路走通之前试错了两次，把结论记下来，避免以后重蹈。

## 二、先明确「取消固定」和「隐藏」的区别

**需求**：任务栏上的开始和搜索要**真的消失**，点击也点不到。

### 错误做法：Opacity = 0

```cpp
SetProperty(bg, zeroValue, opacityIndex);   // Opacity = 0
```

- 元素**仍然占布局空间**
- 元素**仍然参与命中测试**
- 实测结果：视觉上看不见了，**但点原来的位置照样能点开开始菜单**

那不叫取消固定，只是"画成透明的"。

### 正确做法：Visibility = Collapsed

```cpp
GetPropertyIndex(target, L"Windows.UI.Xaml.UIElement.Visibility") -> idx=471
CreateInstance(L"Windows.UI.Xaml.Visibility", L"1")            // 1 = Collapsed
SetProperty(target, collapsed, 471)                            // -> S_OK
```

- **不占布局空间** —— 后面的元素顶上来
- **不参与命中测试** —— 点不到了

**实测验证**：点击原开始按钮位置 `(40, 1560)`，开始菜单**没有打开**。

### 附带发现：枚举值怎么传

`Opacity` 是 `Double`，`CreateInstance("Windows.Foundation.Double", "0")` 就行。

`Visibility` 是**枚举**，`CreateInstance` 要的是它的**底层数值**：
- 类型名写 `"Windows.UI.Xaml.Visibility"`
- 值写 `"0"`（Visible）或 `"1"`（Collapsed）

## 三、往任务栏里插控件：两条路的对比

### 走不通的路：XAML 诊断的 CreateInstance + AddChild

一开始想当然地用了 XAML 诊断接口：

| 调用 | 结果 |
|---|---|
| `CreateInstance(L"Windows.Foundation.Double", L"0")` | `0x00000000` ✅ |
| `CreateInstance(L"Windows.UI.Xaml.Visibility", L"1")` | `0x00000000` ✅ |
| `CreateInstance(L"Windows.UI.Xaml.Media.SolidColorBrush", ...)` | `0x00000000` ✅ |
| `CreateInstance(L"Windows.UI.Xaml.Shapes.Rectangle", L"")` | **`0x8000FFFF`** ❌ |
| `GetCollectionCount(TaskbarFrame, &n)` | **`0x80070490`** ❌ |

**结论**：
- `CreateInstance` **只能造值、枚举、画刷这类"数据对象"，造不出 UI 控件**。
  这套 API 是给调试器读改属性用的，设计上就不支持创建控件。
- `TaskbarFrame` **不是集合容器**，没有能挂子元素的位置。

### 走得通的路：进程内直接调 Windows.UI.Xaml

关键前提：**`GlassTAP.dll` 本身就在 explorer 进程里，而且跑在 XAML 线程上**。
这是前面所有注入工作的副产品，也是这条路能成立的基础。

四步：

```cpp
// 1. 从句柄拿回真实对象
//    ⚠ 关键接口：GetIInspectableFromHandle
//    我们一直在用它的反向函数 GetHandleFromIInspectable，
//    但没用过正向的 —— 有了它才能从诊断句柄拿回真实 C++/WinRT 对象。
::IInspectable* raw = nullptr;
g_diag->GetIInspectableFromHandle(handle, &raw);

// 2. 转成公开的容器类型
//    ⚠ TaskbarFrame 转不成任何公开 Panel（explorer 私有类）。
//    要遍历树，找真正是 Windows.UI.Xaml.Controls.Grid 的那个节点。
//    实测：树里确实有标准 Grid，能转成功。
auto grid = keep.try_as<wux::Controls::Grid>();
// 实测输出：Grid=1 Canvas=0 StackPanel=0 RelativePanel=0 Panel=1

// 3. 纯 C++/WinRT 造控件（完全不走 XAML 诊断）
wux::Controls::Button btn;
btn.Width(40); btn.Height(32);
btn.HorizontalAlignment(wux::HorizontalAlignment::Left);
btn.Background(wux::Media::SolidColorBrush(...));

// 4. 直接调 XAML API 挂上去
grid.Children().Append(btn);   // -> 成功
```

**实测日志**：
```
xaml: 岛台宿主 = Grid (Windows.UI.Xaml.Controls.Grid)
xaml: ✅ 岛台按钮已插入任务栏（宿主子元素数 = 3）
probe: 类型 Windows.UI.Xaml.Controls.Button      ← 树里能看到我们的按钮
```

## 四、点击怎么处理

用 XAML 的 `Tapped` 事件，不用自己的窗口：

```cpp
btn.Tapped([](auto&&, const wux::Input::TappedRoutedEventArgs&) {
    ::InterlockedExchange(&g_islandTapped, 1);
});
```

**为什么这么做**：点击区域完全跟随元素，任务栏移动/缩放时不用手动对齐。

**跨进程传点击**：
1. 回调在 explorer 的 UI 线程上执行，**只置一个标志位**（不能做耗时操作，会卡住任务栏）
2. 主程序通过共享内存通道发 `ConsumeIslandTap` 命令
3. DLL 侧 `InterlockedExchange(&flag, 0)` 取走并清零，返回值告诉主程序这次有没有点击

**实测**：点击按钮 → 日志出现 `xaml: 岛台按钮被点击（Tapped 事件）` ✅

## 五、布局时踩的坑

### 坑 1：不设 HorizontalAlignment 会被拉伸

Grid 的子元素默认拉伸到整格 —— 按钮会变成横贯任务栏的一条。

### 坑 2：Alignment 决定停在哪

`Right` → 贴到 Grid 最右端（实测出现在设置图标附近）
`Left` + `Margin` → 停在最左端（原开始按钮位置）✅

### 坑 3：单位是 DIP 不是物理像素

XAML 用逻辑像素。150% 缩放下 `1 DIP = 1.5 物理像素`。

### 坑 4：TransformToVisual(nullptr) 给的不是屏幕坐标

实测拿到 `(1666, 8)`，但任务栏在屏幕 `(0, 1528)`。

它转的是 **XAML 树内部坐标系**。要拿屏幕坐标得叠加任务栏窗口位置，
或者用 `XamlRoot` 的坐标转换。目前用"红色背景 + 截图"来人工定位，
正式实现里应该走 `XamlRoot` 那条路。

## 六、还遗留的问题

1. **explorer 重启 / 分辨率变化后元素会丢** —— 需要重新插入。
   现有的"补抓"机制（`kIslandCatchupTimer`）能覆盖一部分。

2. **位置要精确控制** —— 目前靠 `Margin` 估算。
   正式版应该根据任务栏的 DPI 和图标区起点动态算。

3. **图标字体**：`Segoe MDL2 Assets`（不是 `Segoe UI Symbol`，
   后者没有私用区码位，会显示空方块）。

4. **稳定性**：往 explorer 的 XAML 树里塞控件属于非官方用法，
   需要多测几轮，确认不会让任务栏崩。
