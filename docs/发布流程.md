# 发布流程

从改完代码到发布到 GitHub 的完整步骤。所有脚本都在仓库的 `tools/release/` 里（打包与发布用）。

---

## 0. 一次性准备

| 项目 | 要求 |
|---|---|
| 编译器 | Visual Studio 2022（Build Tools 即可）+ Windows SDK |
| CMake / Ninja | VS 自带 |
| Python | 用来跑打包脚本（任意 3.8+） |
| GitHub 登录 | 装好 **GitHub Desktop** 并登录（脚本会复用它存在 Windows 凭据管理器里的 token） |

`tools/release/` 下的三个文件：

| 文件 | 作用 |
|---|---|
| `pack_installer.cmd` | 一键出包：编译安装程序 stub → 内嵌载荷 → 生成 `hotrainy_installer.exe` + `hotrainy_setup.zip` |
| `pack_installer.py` | 上一步实际干活的 Python（把 `dist_v3\` 里的文件追加到 stub 末尾 + 写 footer） |
| `publish.ps1` | 一键发布：建仓库（幂等）→ `git push` → 建 Release → 上传附件 |

> ⚠️ 这三个脚本里写的是**绝对路径**（`C:\hot_rain\...`）和**当前版本号**，换机器或发新版本时改脚本开头的变量即可。

---

## 1. 改代码 → 完整构建

改了**头文件**之后务必完整重建（本项目的 obj 布局很敏感，曾因陈旧 obj 出现过两次真实崩溃）：

```bat
:: 在 "x64 Native Tools Command Prompt for VS 2022" 里
cd hotrainy
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -B build
ninja -C build -t clean
cmake --build build -j4
```

---

## 2. 更新版本文档

1. **`docs/releases/`**：新建（或复制上一版改）`v<版本>.md`，写成**面向用户的产品说明**——功能、下载安装、运行环境、使用速查、校验和、源码构建、许可。**不要写"本版修复了 xx"** 这类内部迭代记录。
2. **`CHANGELOG.md`**：追加一条新版本条目。
3. **`README.md` / `README.en.md`**：如果有新的设置项或用法，补上；截图有变化就换 `screenshots/`。
4. Release 里的下载链接、tag 名字如果变了，同步改 `docs/releases/v<版本>.md` 顶部的 Tag/Title。

---

## 3. 出包

把要发布的程序文件放进 `dist_v3\`（至少要有 `hotrainy.exe`、`GlassTAP.dll`、`GlassBoot.dll`、`使用说明.txt`、`uninstall.cmd`、`install.cmd`），然后：

```bat
pack_installer.cmd
```

产出：

```
hotrainy_installer.exe   单文件安装程序（stub + 内嵌载荷）
hotrainy_setup.zip       里面只有上面那个 exe（发给别人的就是这一个）
```

**自测建议**（不碰你正在用的安装）：

```bat
hotrainy_installer.exe /S /D=D:\tmp\hotrainy-test
```

静默装到临时目录，检查是否 5 个文件齐全、注册表是否**没有**被写自启项。测完删掉该目录即可。

记下两个文件的 **SHA256**（发布说明里要写）：

```powershell
Get-FileHash hotrainy_setup.zip -Algorithm SHA256
Get-FileHash hotrainy_installer.exe -Algorithm SHA256
```

---

## 4. 提交并推送

**方式一：GitHub Desktop**（推荐给不熟命令行的）

`File` → `Add local repository` → 选仓库目录 → 左下角填写提交信息 → `Commit to main` → `Push origin`

**方式二：脚本**（顺带把 Release 也发了）

```bat
发布到GitHub.cmd        :: 内部调用 publish.ps1
```

脚本会依次做：

```
[1] 读取 GitHub 凭据（GitHub Desktop 登录留下的 token，不打印、不落盘）
[2] 确认账号
[3] 创建仓库（已存在则跳过，可反复运行）
[4] git push（用临时 Authorization 头，不改 remote 里的密码）
[5] 创建/复用 Release，正文自动从 docs/releases/<版本>.md 抽取
[6] 上传 hotrainy_setup.zip 与 hotrainy_installer.exe（同名附件自动覆盖）
```

`publish.ps1` 开头这几个变量按版本改：

```powershell
$RepoDir      = "C:\hot_rain\cpp\hotrainy"     # 仓库路径
$AssetZip     = "C:\hot_rain\hotrainy_setup.zip"
$AssetExe     = "C:\hot_rain\hotrainy_installer.exe"
$RelNotesFile = Join-Path $RepoDir "docs\releases\v1.0.md"
$Tag          = "v1.0"
$RelTitle     = "hotrainy v1.0 — 第一版 / first release"
```

---

## 5. 发布后检查

- [ ] 仓库页 README 渲染正常（中文页顶部的 `English` 互链可用）
- [ ] `Releases` 页能看到 `v<版本>`，两个附件都能下载
- [ ] Release 正文里的 SHA256 与实际附件一致
- [ ] 仓库 `⚙` → Topics 填好（利于被搜索到）：
      `windows-11` `taskbar` `transparency` `win32` `cpp` `desktop-customization`

---

## 6. 约定与注意事项

| 事项 | 说明 |
|---|---|
| Tag 命名 | `v1.0`、`v1.1`…（发布说明文件名与 tag 同名） |
| 版本号来源 | 目前程序内没有版本号字段，版本信息只体现在 git tag 与 `docs/releases/` |
| 脚本幂等 | `publish.ps1` 可以反复跑：仓库/Release 已存在会复用，附件同名会覆盖 |
| 完整重建 | **改头文件后必须 `ninja -t clean` 再构建**，否则可能崩 |
| 自启项 | 安装程序**不写**开机自启；用户想开机启动由程序设置里的开关负责 |
| 卸载脚本 | `uninstall.cmd` 会连配置、日志、壁纸一起删；它还会**重启一次资源管理器**来释放注入的 DLL（这是必须的） |
| 开源不可撤回 | 一旦以 MIT 发布某个版本，该版本永久可被任何人使用。若想保留"以后闭源"的余地，别随意合并外部 PR，或用 CLA |

## 附：一次完整发版的命令清单

```bat
:: 1. 完整重建
cd /d C:\hot_rain\cpp\hotrainy\build
ninja -t clean && cmake -G Ninja -DCMAKE_BUILD_TYPE=Release .. && ninja -j4

:: 2. 把产物和脚本同步到发布目录 dist_v3（hotrainy.exe / 两个 DLL / 说明 / 两个 cmd）

:: 3. 出包
C:\hot_rain\pack_installer.cmd

:: 4. 静默自测
C:\hot_rain\hotrainy_installer.exe /S /D=D:\tmp\hotrainy-test

:: 5. 取哈希填进 docs/releases/v<版本>.md

:: 6. 更新 CHANGELOG.md 与 README（如有变化）

:: 7. 一键发布（建/复用仓库 + push + Release + 附件）
C:\hot_rain\发布到GitHub.cmd
```
